# 研究背景（Research Context）

更新日期：2026-10-08。本文件保存项目范围、长期目标和研究原则；当前进度与下一步见 [研究状态](research_state.md)。

## 1. 项目定位与目标

毕业论文题目为**《信道图谱表示学习及其在无线感知中的应用研究》**。本项目负责第一个工作：以导师提供的扩散精修信道图谱基线（diffusion-refined channel charting baseline）为基础，研究信道图谱（Channel Charting）的表示构建与改进，形成问题明确、机制有依据、能够实验验证的研究贡献。

第二个无线应用工作和毕业论文整体组织将由另外的项目负责；它们在这里仅作为研究背景，不构成本项目的待办任务。技术流程的两个阶段均属于第一个工作，不能与论文的两个工作混同。

基线是可复用的起点和比较对象，具体创新方法仍需证据支持。允许否定某个优化方案；不因前期投入继续无效路线，也不默认重新进行跨领域选题。若需调整基线之外的技术环节，应说明其与图谱表示问题的直接关系。

## 2. 基线归属与技术边界

第一阶段（Stage 1）继承已有的图谱生成流程：

```text
信道状态信息（Channel State Information，CSI）
→ 角度时延谱（Angle-Delay Profile，ADP）与时间戳融合相异度
→ 20 近邻图（k-nearest-neighbor graph，kNN）
→ 最短路径测地距离 D_geo
→ 孪生前向图谱映射函数（Siamese Forward Charting Function，FCF）
→ 初始图谱 Y0
```

第二阶段（Stage 2）是导师提供的后处理精修基线（post-hoc refinement）：

```text
Y0 + D_geo
→ 测地邻居图与局部尺度权重
→ 图拉普拉斯（graph Laplacian）/ Tikhonov 正则化
→ 精修图谱 Z
```

不能把继承的整个 `CSI → Z` 流程统一描述为新增贡献。两个阶段的图定义和距离用途必须分开；同一份 `D_geo` 用于 FCF 训练目标和第二阶段建图，是流程事实，其是否保留或放大误差需要实验验证。

仿射对齐误差（affine-aligned error）和邻域指标用于评价图谱表示质量。它们不能自动证明实际无线应用效果、未见样本能力或部署性能；全数据上的传导式评估（transductive evaluation）与留出评估（held-out evaluation）应分别解释。样本外扩展（out-of-sample extension，OOS）属于表示能力探索，不等于第二个无线应用工作。

## 3. 研究与证据原则

- **问题先行**：先明确图谱存在什么问题、为什么值得解决，再提出方法；不以换模块、调参和事后寻找解释为主要研究方式。
- **创新判断有来源**：针对具体机制核对最接近的已有工作（closest prior work），区分图谱构建、训练、对齐、后处理和样本外扩展。某技术未用于当前项目或文献数量少，都不足以证明创新性（novelty）。
- **通用方法迁移不自动成为贡献**：使用图神经网络（Graph Neural Network，GNN）、扩散、图重连、注意力、Transformer 或通用去噪工具时，应说明信道图谱特有的问题、信息或约束，以及为何需要该机制。
- **最小实验可作判断**：进入复杂实现前，明确问题、证据、已有工作差距、假设、机制、干预因素、对照、指标、预期观察、最小实验、证伪条件（falsification criterion）和消融策略（ablation）。实验应能区分机制与简单替代解释。
- **结论分层**：区分代码事实、实验观察、文献结论、解释、假设和建议。指标改善、机制支持与创新贡献分别判断，不因反复讨论把假设变成事实。
- **冻结规则与负结果保留**：不在观察结果后修改端点、阈值、分组或停止条件；局部收益和附带损害（collateral degradation）分别报告。失败只否定实际检验的规则，不扩展为整个思想无效。
- **真实位置有边界**：真实位置（ground truth，GT）仅用于明确标记的离线诊断、评估和绘图；不得进入可部署方法的图、权重、门控、损失、特征、目标或推理规则。
- **比较协议一致**：同一可比组（comparable group）且数据、划分、采样步长、随机种子、对齐、指标采样、调参及 GT 使用兼容，才可直接排名；未知项标为待核验。
- **投入受证据约束**：无法说明机制、与已有工作高度重合、验证不可行或收益不稳定时，降低优先级或终止该方案。复用已有代码和证据，避免无判别力的重复实验。

暂定以 **IEEE Transactions on Communications（TCOM）** 为投稿目标和质量参考，关注技术贡献、通信相关性、机制论证、受控对照与结论对应的验证。

## 4. 文档职责与协作方式

- 本文件：长期范围、基线归属、研究与证据标准；不维护实验数值、候选排序或临时下一步。
- [research_state.md](research_state.md)：当前共识、已探索方向、证据边界和当前行动。
- `docs/tasks/`：具体任务的输入、干预、预算、验收与停止条件；历史任务不自动生效。
- [experiment_log.md](experiment_log.md)：实际执行历史与详细解释。
- [experiment_registry.md](experiment_registry.md)：结果路径、角色、协议和可比性索引，不替代研究决策。

每轮解决一个明确问题：核对已有证据 → 说明关键缺口 → 设计最小对照 → 在授权范围内执行 → 记录结论并决定继续或停止。优先复用入口；默认一个任务规格、一个主报告及必要机器产物。研究讨论与代码执行共用仓库记录，不要求在不同应用间反复审批；改变研究范围或冻结设计由用户决定。
