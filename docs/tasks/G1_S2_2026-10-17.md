## 3. E1 — 同一个 Stage-2 算子处理三份初始图谱（先执行）

### 3.1 Research Question / Hypothesis

**RQ-E1：** 对相同的数据、相同的 `D_geo` 与同一个冻结 Stage-2 图和超参数，G1-Identity 或 G1-Graph 能否产生比 B0 更好的 refined chart？真实图传播在 S2 后是否产生额外的收益？

**H-E1（待检验）：** 虽然 G1-Graph 在 Stage-1 与 Identity 接近，但其表示可能经同一 S2 算子得到更高的几何质量；也可能没有额外收益。允许得到 negative / mixed 结果。

### 3.2 冻结的 S2 实验参数

```text
Dataset:                  datasets/adp_old_shard4
N:                        20,997
Stride:                   1
Seed:                     10
Distance source:          results/adp_old_fused/stride1_n20997_seed10/geodesic.npy
Stage-2 graph source:     D_geo （geodesic-neighbor graph，不是 G1 的 fused GCN 图）
top_k:                    512
graph_k:                  128
lambda_smooth:            0.15
iterations:               200
solver:                   原 run_diffusion_refined_charting.py 的 Jacobi 实现
Graph / normalization:    原 build_local_scaled_graph 与 solve_graph_harmonic_refinement（不改公式）
```

分别对三个 `embedding.npz` 输入调用**同一个** S2 函数：

```text
B0 embedding          → B0+S2
G1-Identity embedding → G1-Identity+S2
G1-Graph embedding    → G1-Graph+S2
```

三次 refinement 的区别只允许来自初始 embedding `Y`。`D_geo`、邻居表、S2 图、S2 超参数和 solver **完全相同**。建议只构图一次、复用同一个 graph 对三个 `Y` 分别求解，提高一致性与效率。若想检查历史结果是否可复现，可在运行结束后比较已保存的 B0+S2（存在时），不能默默更改 solver 以逼近历史指标。

### 3.3 避免旧 S2 脚本污染源 distance-run

旧 `run_diffusion_refined_charting.py` 会将 `geodesic_top512.npy` 缓存写到 `distance-run`，而且三个输入的默认 run_name 都会相同。**不得直接重复调用旧 CLI 导致覆盖或污染源目录。**

推荐做法：在 `methods/g1_acf_graph_fcf/` 下新增隔离的 orchestrator，例如 `run_stage2_comparison.py`，仅从原脚本 `import` 三个函数，并实现：

1. 根据当前 `geodesic.npy` 重新计算一份 top-512 neighbor 缓存，并放入**本轮新实验输出根目录**（而不是 `distance-run`）；B0、G1-Identity、G1-Graph 三组必须共同复用这一份新缓存。原仓库已有的旧缓存仅作只读复现对照，不复制为正式输入，也不因 shape 正确就视为可信；
2. 从 `geodesic.npy` 重建 S2 图一次，对三个 embedding 使用**同一个图对象**；
3. 三个输出分别独立目录，严禁覆盖原 `B0`、`G1`、旧 `S2` 的任何 `embedding.npz`、`result.json`、`chart.png`、checkpoint；
4. 保存共享 `S2` 图缓存元数据和必要的 hash/签名，用于审计三组确实共用一个图；
5. 使用原 S2 Jacobi 迭代，不修改迭代次数，不新增优化器或自适应调参；可额外**只记录**迭代后线性系统残差作为数值诊断，不以它调整 200 次冻结迭代。

关于复现：如已有历史 B0+S2，检查其实际 `graph_k/lambda/top_k/iterations`、dataset/seed/index、cache 来源。若历史使用过不同的 neighbor tie 顺序或缓存，必须明确记录；不要为了匹配历史数值引入新算法。正式比较优先使用本轮统一函数重新算出的三个 `+S2`。

## 4. E2 — Frozen checkpoint 图传播敏感性与残差贡献诊断

> E1 完成并保存后执行；**不要重新训练或重新选择 checkpoint**。如 E1 遇到输入缺失，先报告；只有 E2 所需文件齐全且 E1 不涉及的数据身份问题没有扩散时，才允许独立运行 E2。

### 4.1 Research Question

- **RQ-E2a：** 用原已训练好的 G1-Graph best checkpoint，推理时将 `A_graph` 改为 `I`，预测结果变化有多大？
- **RQ-E2b：** 每层 GCN 的 residual 更新量 `delta` 相对传入的节点表征 `h` 有多大？
- **RQ-E2c：** Graph 的传播是否被有效使用、但未带来净收益？还是在当前模型中作用确实很弱？

### 4.2 固定模型与推理矩阵

不训练，不更改 `model_best.pt` 和 `BatchNorm` 统计，必须 `model.eval()`、关闭 dropout。在相同特征与相同节点顺序下执行：

| 固定权重 | 邻接 | 类别 | 目的 |
|---|---|---|---|
| Graph `model_best.pt` | `A_graph` | 已训练配置复现 | 应与已保存 Graph embedding 一致 |
| Graph `model_best.pt` | `I` | **post-training sensitivity probe** | 检查 Graph 模型对消息传播的依赖程度 |
| Identity `model_best.pt` | `I` | 已训练配置复现 | 应与已保存 Identity embedding 一致 |
| Identity `model_best.pt` | `A_graph` | 可选交叉 probe | 补充估计分布外图替换的响应，不用于主排名 |

注意：Graph checkpoint 临时换 `I` 会改变训练时的传播输入分布。这是**敏感性诊断**，**不能被当成重新训练的 Identity 对照**。原先的 Graph-vs-Identity full training 才是本轮最重要的模型对照。

### 4.3 观测量（不需要 GT 作为优化输入）

1. **复现校验**：两种原生“checkpoint + 正常邻接”推理输出与旧 `embedding.npz` 各自全节点比较；固定容差如 `atol=1e-4, rtol=1e-4`（环境确有数值差异时报告并说明），不一致先停下排查 checkpoint/特征/BN/device，不能继续分析错误表征。
2. **无 GT 的 stress 指标**：复用相同 `200,000` 固定验证点对（从原 G1 `validation_pairs` 规则重建），核验 `validation_pair_hash` 与记录相等，计算同一 `siamese_loss`/margin。记录正常 vs 替换邻接的绝对/相对变化。
3. **节点 embedding 变化**：以同一冻结 checkpoint、同一输出头下的 raw 坐标直接计算 `mean/median/P95` 的 `||Y_graphAdj - Y_identityAdj||_2`，作为主要敏感性统计。这里不新增刚性/相似变换对齐流程。需要报告 Channel Chart 质量和图片时，继续复用项目既有 `common_metrics` 与 `plot_chart`，按统一协议分别对 GT 做 affine 对齐；GT 只用于离线评价和绘图，不用于 checkpoint、图或参数选择。
4. **每层残差贡献**：对 `ResidualSparseGCN` 记录输入 `h`、归一化消息 `A @ h`、`delta = ReLU(LN(Linear(message)))` 与 `h_next=h+delta`（eval 模式 dropout 不起作用）。逐层报告 `||delta||/(||h||+eps)` 的中位数、P10/P90，以及 `||A@h-h||/(||h||+eps)` 的分布；避免只报告全局平均使局部异常被掩盖。
5. **可选位置诊断**：在所有上述无标签统计完成后，可以使用 UE 坐标**仅作离线评价/可视化**，将受传播影响大的节点标到真实轨迹以解释空间分布；不使用 GT 修改图和模型。

不要将 `||delta||/||h||` 单个数值直接解释为传播“有效/无效”：即使 delta 大，也可能主要来自节点自身和可学习线性层，需要结合 `Graph checkpoint @ A_graph/I` 的敏感性结果综合判断。

### 4.4 E2 结果解释准则

- 图替换几乎不改变 embedding/验证 stress，并且消息-残差差异很小：支持**低敏感性**解释；不能直接证明模型完全没有学习图结构。
- 图替换明显改变 embedding/验证 stress，但训练好的 Graph 仍不优于训练好的 Identity：说明图信息确实影响网络输出，**当前影响未形成额外几何收益**。
- 图替换导致验证 stress 明显变差：表明已训练 Graph 对该邻接有依赖，**仍不等价于真实 Graph 相对重新训练 Identity 的收益**。
- 若上述统计自相矛盾，保留完整诊断并标记 unresolved，禁止为了得出预设结论而调指标口径。
